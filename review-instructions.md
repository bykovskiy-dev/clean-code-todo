# Ревью решения Clean Code

## Цель

Прочитать итоговое TODO-приложение и найти оставшиеся проблемы читаемости. Ничего не исправлять.

## Границы

Проверять только то, что задание относит к части 2:

- мёртвый код;
- дублирование обработчиков и логики;
- имена, которые не читаются без комментария;
- комментарии, которые пересказывают код;
- функции, которые нельзя прочитать целиком.

Не трогать и не предлагать переписывать:

- поведение из чек-листа задания;
- настройку ESLint, Prettier и Husky;
- файл `.github/workflows/check.yml`;
- внешний вид страницы.

Не применять DRY, KISS и YAGNI «для галочки». Замечание ставить только там, где из-за проблемы следующую правку легко сделать не в том месте.

## Критерий готовности

Ревью закончено, когда каждая найденная проблема записана в отчёт и у каждой есть место, суть, условие проявления и способ проверки. Если по категории проблем нет, в отчёте так и написано.

## Формат вывода

Отчёт записать в `review-report.md` на русском. Замечания сгруппировать по категориям из списка выше. У каждого замечания четыре части:

1. Место в коде.
2. Проблема.
3. Условие, при котором она проявляется.
4. Способ проверить исправление.
